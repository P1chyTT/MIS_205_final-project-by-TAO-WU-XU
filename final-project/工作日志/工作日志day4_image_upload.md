## 一、功能需求分析

### 1.1 用户需求
- 拼单用户希望看到物品的实际照片，确保商品质量
- 找搭子用户希望看到活动海报或场地照片，了解活动详情
- 图片能增加帖子的可信度和吸引力

### 1.2 技术需求
- 支持单张或多张图片上传
- 图片大小限制：最大5MB
- 支持常见图片格式：JPG、PNG、GIF、WebP
- 图片存储：使用Supabase Storage
- 图片显示：帖子卡片显示首图，点击可查看画廊

---

## 二、数据库设计变更

### 2.1 Schema 更新
在 `posts` 表中添加两个新字段：
- `image_url TEXT` - 帖子主图URL（第一张图片）
- `image_urls TEXT[] DEFAULT '{}'` - 帖子所有图片URL数组

### 2.2 索引优化
- 为 `image_urls` 字段创建GIN索引，支持数组查询
- 保持与现有索引的一致性

### 2.3 Storage 配置
- 创建 `post-images` Storage桶
- 设置公共访问权限
- 文件大小限制：5MB
- 允许的MIME类型：image/*

## 三、前端实现

### 3.1 发布/编辑表单
- 在详细描述下方添加图片上传区域
- 支持拖拽/点击上传
- 实时图片预览
- 图片操作：删除单张、清空所有、添加更多

### 3.2 图片上传流程
1. 用户选择图片文件
2. 前端验证文件大小和类型
3. 显示预览图片
4. 提交帖子时上传到Supabase Storage
5. 生成公开URL并保存到数据库

### 3.3 帖子显示优化
- 帖子卡片显示首张图片
- 多图显示数量徽章（+N）
- 点击图片打开画廊模式
- 画廊支持缩略图导航和键盘操作

### 3.4 编辑功能增强
- 编辑时显示已有图片
- 支持删除已有图片
- 支持添加新图片
- 保持图片URL数组的同步更新

## 九、遇到的问题与解决方案

### 9.1 Supabase Storage 权限
**问题**：匿名用户无法直接创建Storage桶  
**解决方案**：在Supabase控制台手动创建，或使用服务端密钥

### 9.2 图片数组更新
**问题**：更新图片数组时可能丢失已有图片  
**解决方案**：先获取现有数组，再合并新图片

### 9.3 移动端适配
**问题**：移动端上传体验不佳  
**解决方案**：优化触摸事件，提供移动端专用界面
